# 治理协作流程草图：DAO 贡献追踪器

## 选定场景

**社区**：AI × Web3 School 共学社区

**流程**：追踪学习者在 GitHub 和论坛上的贡献，生成可验证的链上信誉分数。

---

## 五步流程草图

| 步骤 | 做什么 | 数据来源 | 执行者 | 确认方式 |
|------|--------|----------|--------|----------|
| ① 抓取 | 从 GitHub 拉 PR、commit、review 记录；从论坛拉提案、评论 | GitHub API + 论坛 API | AI 自动 | 无需人确认 |
| ② 清洗 | 过滤刷量行为（typo-only PR、重复提交）、去广告、合并同类贡献 | 步骤① 原始数据 | AI 自动 | 无需人确认 |
| ③ 打分 | 按社区投票通过的权重规则计算贡献分（代码 > 文档 > 评论；质量 > 数量） | 步骤② 清洗后数据 | 人定规则 + AI 执行 | 规则由 DAO 投票通过 |
| ④ 存证 | 贡献分数写入链上合约，公开可查、不可篡改 | 步骤③ 分数结果 | 合约自动 | 上链即不可逆 |
| ⑤ 纠错 | 任何人发现 AI 误判（如低估安全审计贡献），提交修正提案 | 步骤④ 链上记录 | 社区全员 | 修正需 DAO 投票通过 |

---

## AI vs 人工边界

### AI 可以做的（无需确认）

- 批量拉取 GitHub 和论坛数据
- 识别明显的刷量行为（单行修改、重复提交）
- 按既定规则计算分数（公式固定，执行透明）
- 将结果写入链上合约（自动化触发）

### 必须人工/治理确认的

- **打分规则本身**——什么人定，需要 DAO 投票
- **争议判断**——AI 低估或高估某个贡献时，人工提起修正
- **规则更新**——社区成长后，加减权重的逻辑需要重新投票

### AI 总结 vs 治理决策

| 类型 | 例子 | 性质 |
|------|------|------|
| AI 总结 | "本周 Top 3 贡献者：张三（3 PR，120行）、李四（5 review）、王五（2 提案）" | AI 输出，仅供参考 |
| 治理决策 | "将张三的贡献权重从 0.8 调整为 1.5（因其发现致命漏洞）" | 必须 DAO 投票 |

---

## 为什么贴合 Identity/Reputation 主线

贡献追踪 = 信誉的数据底座。没有客观、可验证的贡献记录，Agent 的信誉就是空中楼阁。

**逻辑链**：贡献 → 追踪 → 打分 → 链上存证 → 信誉信号 → 身份可信

这个流程本质是在回答「这个 Agent/人的信誉从哪来」——不是自说自话，不是平台背书，而是**公开可查的、人定规则 + AI 执行 + 链上存证的贡献数据**。
