## 学习笔记：LLM

### 核心认知

LLM 的本质是**概率模型**，不是事实数据库。关键推论：

> 模型输出是候选结果，不是事实本身；模型能力是推理入口，不是最终验证。

在产品中 LLM 的角色定位：
- ✅ 理解、归纳、生成、规划
- ❌ 事实来源、权限判断、最终执行

### 关键概念

| 概念 | 一句话 | 产品意义 |
|------|--------|---------|
| Token | 文本切分单元，≠ 一个字 | 影响成本、上下文容量、长文档处理策略 |
| Embedding | 文本→向量，量语义相似度 | RAG 搜索、推荐、聚类的基础 |
| Transformer | Attention 找模式 | 模式组合能力强，但不等于稳定数据库 |
| Hallucination | 编造合理但不真实的内容 | 带执行能力的系统需要外部校验 |
| Multimodal | 文本+图+音+视频 | 让 AI 读懂更多真实工作界面 |

### 产品启示

LLM 在 AI×Web3 产品栈中的位置：
```
理解/生成层（LLM） → 用户意图 → 可讨论的计划
数据层（RPC/索引器/预言机） → 链上事实
编排层（Prompt/Context/RAG/Agent） → 组合能力
执行层（工具/钱包/合约） → 真实动作
安全层（Guard/Simulation/人工确认） → 守住边界
```

核心理念：**LLM 越靠近执行层，越要把它输出变成可验证对象。**
