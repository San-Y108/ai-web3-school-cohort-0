# 大语言模型（LLM）、提示词（Prompt）、上下文（Context）

基于 Handbook 整理的系统笔记，覆盖 AI 基础核心三章。

---

## 大语言模型（LLM）

LLM 不是"一个会聊天的黑盒"——它是把大量文本、代码和多模态信号压进参数的概率模型。它的工作方式不是查数据库，而是算概率：给定前面的 token，下一个 token 最可能是什么。

### Token

Token 是模型处理文本的基本单位。一个汉字、一个英文词、一个符号都可能被切分成一个或多个 token。长文档、代码、JSON 都容易把上下文撑满——不能只看"页面短"就以为 token 少。

Token 直接影响三件事：
1. 上下文能放多少内容
2. 调用成本是多少
3. 模型能不能完整看见关键信息

### Embedding

Embedding 是把文本映射成向量，用来衡量"语义上是否接近"。适合搜索、聚类、推荐和 RAG，但不能替代事实校验——向量相似度只说明内容接近，不等于结论正确。

### Transformer

Transformer 是现代 LLM 的核心架构，关键靠 attention：模型能在生成时关注输入的不同位置，学习词、代码、事实和上下文之间的关系。但它的能力是找模式，不是当数据库。

### Hallucination（幻觉）

模型生成看起来合理但无法验证的内容。在普通问答里是质量问题，在带执行能力的系统里是流程风险——错误参数、错误权限解释都可能进入自动化链路。

应对方式不是"写更好的 prompt"，而是接到外部校验：来源引用、schema 校验、规则检查、人工确认。

### 关键原则

> LLM 生成的是概率上合理的输出，不是天然可信的事实。**它是推理层，不是真相源。**

## 提示词（Prompt）

Prompt 不是你"怎么问 AI"，而是**你和一个执行系统之间的接口协议**。它要告诉模型：任务是什么、哪些信息可用、输出什么格式、不确定时怎么做。

### Instruction（指令）

应该拆成四段：
1. 任务目标
2. 可用输入
3. 禁止行为
4. 输出格式和失败格式

特别要区分"解释"和"执行"——可以整理资料，但不能假装已经验证。

### Few-shot（少样本）

放少量示例让模型模仿。适合"很难一句话说清"的任务，但要跟 eval 一起维护，否则旧示例反而会误导模型。

### Structured Output（结构化输出）

让模型返回固定格式（JSON、函数参数），后续代码才能检查、拒绝、记录和回归测试。

### Prompt Injection

攻击者通过用户输入、文档、网页让模型忽略原始规则。应对核心不是写"不要被注入"，而是：
- 外部内容标记为不可信数据
- 工具调用前做参数校验
- 敏感动作强制走 allowlist 和 human approval
- 不把密钥、主权限交给模型

### 关键原则

> Prompt 是软约束，不是安全边界。**真正的边界由代码、权限、校验和审计来承担。**

## 上下文（Context）

Context 是模型这一次能看到、能使用、能影响的信息空间。**模型的输出只取决于它当前能看到的上下文。** 上下文错了、缺了、过期了，模型再强也没用。

### Context Window

模型一次请求能处理的最大范围。窗口大不等于模型会用得好——长上下文可能"看见了但没抓住重点"。应该配合检索、摘要和结构化数据使用。

### Context Engineering

设计上下文进入模型的方式。一个稳定的 Agent 上下文应该包含：
- 当前任务状态
- 工具返回结果
- 可信数据来源
- 外部检查结果
- 用户原始意图
- 系统禁止事项

### Memory

跨会话保留的信息（用户偏好、历史任务）。可以提高体验，但**不能替代实时授权**——过去允许的动作不代表现在仍然允许。涉及身份、权限、资产的记忆必须重新绑定当前授权。

### Knowledge Base

可检索的外部知识库。需要维护来源、更新时间、版本和适用环境，否则 RAG 只会把旧错误更稳定地送进模型。

### 上下文的分层（推荐）

1. **指令层** — 系统规则、工具使用规则、禁止事项
2. **任务层** — 用户目标、本次会话参数
3. **事实层** — 链上状态、工具结果、simulation
4. **知识层** — 文档、标准、历史案例
5. **记忆层** — 用户偏好、项目配置

### 关键原则

> 模型只能基于它看见的上下文行动；**系统必须决定什么能进上下文、带着什么身份进去、过期后怎么退出。**

---

## 三章的核心关联

- **LLM** 负责推理和生成，但它是概率层不是真相源
- **Prompt** 定义任务和格式，但只是软约束不是安全边界
- **Context** 决定模型看见什么，系统必须治理好信息的进出

三者配合才能让 AI 在带执行能力的系统（如 Web3 链上操作）中可靠工作：Prompt 定任务 → Context 给数据 → LLM 生成 → 代码校验 → 人工确认。
