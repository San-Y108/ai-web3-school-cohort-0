## 钱包（Wallet）学习笔记

### 一、钱包的本质

- 钱包不是「登录按钮」，是**保管私钥、签名、发交易**的工具
- 私钥 = 链上控制权，丢了无法找回，没有客服可联系
- 钱包形态：浏览器插件（MetaMask）、手机 App（Trust Wallet）、硬件设备（Ledger）

### 二、钱包的三种动作

| 动作 | 花 Gas 吗 | 改链上状态吗 | 风险等级 |
|------|----------|------------|---------|
| 连接钱包 | 否 | 否 | 低 |
| 签名消息 | 否 | 不直接改 | 取决于签名内容 |
| 发送交易 | 是 | 是 | 高，不可撤回 |

- 连接 ≠ 授权，只是暴露地址
- 签名免费 ≠ 签名安全，可能授权他人动用资产
- 发送交易一旦上链不可撤回

### 三、Gas（手续费）

- Gas 是支付给验证者的链上执行费用
- 用原生币支付（以太坊用 ETH，Polygon 用 MATIC）
- 费用不固定，网络拥堵时更贵
- **交易失败也会扣 Gas**
- 账户必须同时有转账资产 + 足够原生币付 Gas

### 四、Explorer（区块浏览器）

- 用于查看链上事实的网站（以太坊用 etherscan.io）
- 通过交易哈希（TxHash）查询交易状态

关键字段：

| 字段 | 含义 |
|------|------|
| Status | 成功 / 失败 |
| From / To | 发起方 / 接收方 |
| Value | 转账的原生币金额 |
| Token Transfers | Token 流动情况 |
| Gas Used | 实际消耗的 Gas |

> 核心原则：浏览器显示的是链上事实，其他都只是「说法」。

### 五、交易的完整生命周期

1. 用户点击 dApp 按钮（发起请求）
2. 钱包弹窗展示细节（等待确认）
3. 用户确认，钱包签名并广播
4. 交易进入 mempool（排队等候）
5. 验证者打包进区块
6. 链上执行（成功或 revert）

每一步都可能失败。**点按钮 ≠ 交易完成。**

### 六、账户类型

**EOA（外部拥有账户）：**
- 由单一私钥控制
- 不能换私钥、不能细分权限、不能自动化
- 私钥丢失 = 资产永久丢失

**智能账户（了解即可）：**
- 可换控制密钥、可多签、可限额、可社交恢复
- 属于「账户抽象」范畴，是行业对 EOA 缺陷的解决方案

### 七、助记词（Mnemonic）

- 12 或 24 个单词，用于恢复私钥
- 任何网页、客服、AI 索要助记词 = 危险
- 正确流程：在钱包 App 内部恢复，dApp 只请求连接

### 八、AI Agent 与钱包的边界

| 角色 | 职责 |
|------|------|
| AI Agent | 解释交易、准备参数、检查风险、提供建议 |
| 钱包 | 展示细节、获取用户签名 |
| 智能账户 | 执行预设约束（额度、白名单） |
| 用户 | 最终决策和授权 |

硬规则：

- AI 不应持有私钥
- AI 不应绕过钱包自行签名
- 签名和授权必须保留人工确认

### 总结

- 钱包 = 密钥管理器 + 签名工具 + 交易广播器
- 连接、签名、发交易是三种完全不同的操作，风险逐级升高
- Gas 是使用链的成本，交易失败也扣
- Explorer 只看链上事实，不信任任何人的「说法」
- 助记词只在钱包内部用，任何外部索要都是诈骗
